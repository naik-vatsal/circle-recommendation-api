# Circle Recommendations - Technical Design

**Goal.** Help members discover relevant, available peer-support Circles and understand the fit. A sparse profile never prevents discovery. Treat participation and sustained connection as intended product outcomes; clicks alone are insufficient.

**Implementation.** FastAPI serves `GET /users/{user_id}/recommendations`, with a bounded limit, optional scores, a request-only topic choice and an exact format filter. `GET /topics` lists valid choices. SQLite holds the supplied users, Circles, memberships, taxonomy and activity. Startup imports atomically and preserves existing data. Each request owns a read-only connection and consistent read transaction. Typed responses, validation and interactive OpenAPI documentation expose the contract. No external model service is required.

**Eligibility and relevance.** Exclude existing memberships, unlisted groups, full/overfull groups, and Circles without both a recent timestamp and nonzero feed/chat volume. Null capacity means uncapped. Score weights are interests (55%), membership topics (10%), activity (25%), observed participation (4%) and joining ease (up to 6%). Primary-topic evidence is stronger than secondary tags; unrelated tags never dilute membership affinity. No format preference is assumed. Members can filter by format or replace profile interests for one search without changing stored preferences.

**Participation and explanations.** Activity combines capped logarithmic feed/chat volume, a 14-day recency half-life and mean engagement. A small participation contribution considers distinct observed authors, concentration and activity across relative weeks, shrinking sparse evidence toward zero. A single prolific author earns no participation bonus. Missing feed evidence is not a disqualifier; posting is not proof of inclusion or meeting quality. Responses label primary matches, related suggestions, membership matches and discovery. Related suggestions disclose the actual main topic. Evidence counts describe only the observed feed and never expose author identities.

**Diversity and time.** Greedy selection allows one Circle per primary topic and at most one secondary-interest suggestion, with an overlap penalty and stable tie-breaking. Topic-less groups use known tags; untagged groups stay independent. This cap can suppress useful alternatives, so format filtering happens before selection. Time calculations use the fixture's September 21, 2026 observation time, returned as `as_of`. The 30-day online-activity rule is a conservative assumption: real monthly groups require meeting schedules and leader confirmation. Testing 45/60-day cutoffs changes no candidates here and cannot validate the threshold.

**Validation and tradeoffs.** Tests cover every user, planted scenarios, constraints, concurrent reads, rollback, boundaries, input abuse and counterfactual behavior. A repeatable comparison separates activity/access, topic ranking, diversity and participation effects. Diversity removes 86 repeated-topic slots from the topic-ranked baseline while retaining all attainable stated-topic coverage on this fixture. These are synthetic diagnostics, not relevance labels or causal outcome evidence. No profile polish, prestige, inferred identity or geographic fit is scored.

**Production path.** Add authenticated self-access, rate limits, atomic capacity checks during joining, refreshed feature snapshots and observability. Move to PostgreSQL migrations/pooling, indexed candidate retrieval and precomputed features as needed. Collect consent-based format/schedule preferences; measure accepted joins, sustained participation and member-reported usefulness. Monitor leader request load and group exposure before distributing recommendations using demand signals. Improve duplicate clustering and activity cadence using real feedback before learned ranking. CI runs the tests and verifies the saved evaluation.
